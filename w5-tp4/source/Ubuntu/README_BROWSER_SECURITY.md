# Browser Security - Educational Defense Tools

## 📚 Purpose
This collection teaches **defensive security** by explaining how browser attacks work and how to prevent them. All tools focus on **detection, prevention, and response** - NOT exploitation.

## 🛡️ What You'll Learn

### 1. Attack Understanding (Know Your Enemy)
- How outdated browsers are exploited
- What data attackers target and why
- Complete attack chain from initial compromise to data theft
- Real CVE examples and their impact

### 2. Defense Implementation (Build Protection)
- File integrity monitoring
- Access pattern detection
- Network traffic analysis
- Application sandboxing
- Incident response procedures

### 3. Practical Tools (Hands-On Learning)
- Browser security auditor
- Defense simulator
- Monitoring scripts
- Security checklists

## 🔧 Tools Included

### 1. `browser_security_audit.py`
**Comprehensive security assessment tool**

Performs:
- Browser version checking (detects outdated software)
- Sensitive data location mapping
- File permission auditing
- Password encryption analysis
- Complete attack flow explanation
- Security recommendations
- Monitoring script generation

**Usage:**
```bash
python3 browser_security_audit.py
```

**Output:**
- Identifies security vulnerabilities
- Shows what data is at risk
- Provides actionable recommendations
- Creates monitoring script

### 2. `browser_defense_simulator.py`
**Interactive defense training tool**

Demonstrates:
- File integrity monitoring (detect tampering)
- Access pattern analysis (identify suspicious activity)
- Network traffic monitoring (catch exfiltration)
- Sandboxing techniques (limit damage)
- Incident response (what to do when breached)

**Usage:**
```bash
python3 browser_defense_simulator.py
```

**Features:**
- Step-by-step walkthrough
- Real-time detection demonstrations
- Incident response guide
- Security checklist generator

### 3. `browser_monitor.sh`
**Real-time file access monitor**

Auto-generated by the audit tool. Monitors browser files and alerts on suspicious access.

**Usage:**
```bash
# First install required tools
sudo apt install inotify-tools

# Run monitor
./browser_monitor.sh
```

**Alerts on:**
- Unexpected file access
- Access by unknown processes
- Access at unusual times

- Keep software updated
- Use strong passwords + 2FA

- File integrity monitoring

- Principle of least privilege

- Quick response procedures

### Layer 4: Recovery
**Restore security after breach**
- Incident response plan
- Data restoration
- System hardening
- Lessons learned analysis

## 🚨 Real-World Attack Examples

### Example 1: Chrome CVE-2023-4863 (WebP)
**Vulnerability:** Memory corruption in image processing
**Attack:** Malicious image triggers code execution
**Defense:**
```bash
# Check version
google-chrome --version

# Update immediately
sudo apt update && sudo apt upgrade google-chrome-stable

# Verify patch
# Version must be >= 116.0.5845.187
```

### Example 2: Password Theft via Malware
**Attack Flow:**
1. Victim downloads infected software
2. Malware gains user privileges
3. Reads browser's Login Data SQLite file
4. Decrypts passwords using OS APIs
5. Sends to attacker's server

**Defense:**
```bash
# Monitor Login Data access
inotifywait -m ~/.config/google-chrome/Default/Login\ Data

# Use dedicated password manager
sudo apt install keepassxc

# Enable 2FA everywhere
# Visit: https://twofactorauth.org/
```

### Example 3: Session Hijacking via Cookies
**Attack:** Malware steals Cookies file to hijack logged-in sessions
**Defense:**
```bash
# Secure cookie file permissions
chmod 600 ~/.config/google-chrome/Default/Cookies

# Monitor cookie access
sudo auditctl -w ~/.config/google-chrome/Default/Cookies -p ra

# Use cookie auto-delete extension
# Install: https://chrome.google.com/webstore
```

## 🛠️ Practical Exercises

### Exercise 1: Baseline Your System
```bash
# Run security audit
python3 browser_security_audit.py > baseline_report.txt

# Save for comparison
date >> baseline_report.txt

# Re-run weekly and compare
diff baseline_report.txt new_report.txt
```

### Exercise 2: Monitor File Access
```bash
# Start monitor in background
./browser_monitor.sh &

# Open browser and browse normally
google-chrome

# Check logs for access patterns
cat ~/browser_access_monitor.log

# Identify normal vs suspicious activity
```

### Exercise 3: Simulate Incident Response
```bash
# Pretend you've detected a breach
# Follow these steps:

# 1. Disconnect network
sudo nmcli networking off

# 2. Kill browser
pkill -9 chrome

# 3. Check for malware
sudo clamscan -r --bell -i ~/

# 4. Review recent file access
find ~/.config/google-chrome -type f -mtime -1

# 5. Change passwords from different device
# 6. Enable 2FA
# 7. Reconnect and monitor
```

### Exercise 4: Test Sandboxing
```bash
# Install Firejail
sudo apt install firejail

# Run browser in sandbox
firejail --seccomp --private google-chrome

# Try to access files outside browser profile
# Should fail - sandbox is working!
```
